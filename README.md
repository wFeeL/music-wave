# WaveFeels

Приложение для macOS 26, которое рисует музыку вокруг выреза камеры. Пока играет Яндекс Музыка (или другой выбранный источник), из-под выреза расходятся три полупрозрачные волны: бас, голос и инструменты, высокие частоты. Они строятся по настоящему звуку приложения, а не по таймеру. Цвета берутся из обложки трека. Если навести курсор на вырез, остров раскрывается: обложка, название, прогресс и кнопки управления.

Нужен мак с процессором Apple (arm64) и macOS 26 или новее. Приложение не нотаризовано и не из App Store, поэтому установка немного ручная, зато без платного аккаунта разработчика.

## Установка

Репозиторий закрытый, скачивать нужно из браузера, где вы вошли в GitHub.

1. На странице репозитория открыть Releases и скачать WaveFeels-<тег>.zip из последнего релиза.
2. Распаковать архив и перенести WaveFeels.app в «Программы».
3. В Терминале снять карантин:

```
xattr -dr com.apple.quarantine /Applications/WaveFeels.app
```

4. Открыть WaveFeels.

## Первый запуск

В Dock значка нет, приложение живет в строке меню (иконка с волной). При первом запуске macOS спросит про «Запись системного аудио», нужно нажать «Разрешить». Больше приложению ничего не нужно: ни записи экрана, ни универсального доступа.

Дальше запустить Яндекс Музыку и включить трек. Остров появится у выреза сам и спрячется через несколько секунд после паузы.

Если вопроса не было или вы нажали «Запретить», включить доступ можно вручную: Системные настройки, Конфиденциальность и безопасность, Запись экрана и системного аудио, раздел «Только запись системного аудио».

## Настройки и диагностика

Значок в строке меню открывает меню:

- «Настройки…»: источник звука (Яндекс Музыка, любое приложение из списка, браузер или весь звук системы), чувствительность, режим уровня, задержка волн, ширина крыльев, свечение, запуск при входе в систему и другое;
- «Диагностика…»: уровень сигнала, найденные процессы, состояние захвата и Now Playing, подпись, экраны, доступ к звуку. Кнопка «Скопировать диагностику» кладет весь отчет в буфер обмена, его удобно прислать, если что-то работает не так;
- «Приостановить визуализацию»;
- «Выйти из WaveFeels».

Лог лежит в ~/Library/Logs/WaveFeels/.

## Обновление

Автообновления нет. Новая версия ставится так же, как первая: скачать архив, заменить WaveFeels.app в «Программах», снова выполнить команду с xattr. Разрешение на звук при этом сохраняется, потому что все сборки подписаны одним и тем же сертификатом.

## Удаление

```
rm -rf /Applications/WaveFeels.app ~/Library/Preferences/com.wfeels.wavefeels.plist ~/Library/Logs/WaveFeels
tccutil reset AudioCapture com.wfeels.wavefeels
```

Первая команда убирает приложение, настройки и логи, вторая сбрасывает выданное разрешение на звук.

## Сборка и релизы

Проект собирается Swift Package Manager, без проекта Xcode. Ядро (WaveCore) не зависит от macOS и тестируется на Linux:

```
bash scripts/test-linux.sh
```

Приложение собирается и проверяется в GitHub Actions на раннере macos-26. Workflow mac запускается тегами ci-*, snap-* и full-check-*, результаты уходят в ветку ci-results. Релиз собирает workflow release по тегу v*: он запускает полную проверку, подписывает приложение, делает два архива (основной и update-test для проверки обновления) и публикует их в GitHub Release. Тег с дефисом (например v0.9.0-beta.1) публикуется как предварительный релиз.

## Сертификат подписи

Разрешение на звук привязано к подписи приложения, поэтому сборки подписываются одним самоподписанным сертификатом. Пока репозиторий без секретов, сертификат лежит в signing/ (wavefeels-signing.p12 и password.txt). Репозиторий закрытый, сертификату никто не доверяет, и нужен он только для того, чтобы macOS узнавала приложение после обновления.

Как перенести его в секреты репозитория:

1. На маке, из корня репозитория, закодировать сертификат и скопировать результат в буфер:

```
base64 -i signing/wavefeels-signing.p12 | pbcopy
```

2. В репозитории на GitHub открыть Settings, Secrets and variables, Actions, и создать секрет SIGNING_P12_BASE64, вставив буфер обмена.
3. Создать секрет SIGNING_P12_PASSWORD со значением из signing/password.txt.
4. Убедиться, что сборка проходит с секретами, и удалить каталог из репозитория:

```
git rm -r signing
git commit -m "chore: remove signing files from repo"
git push
```

Сертификат при этом нельзя терять и менять: с новым сертификатом macOS посчитает приложение другим и снова спросит про доступ к звуку. Файл p12 и пароль стоит сохранить у себя вне репозитория.

Если заданы оба секрета, workflow берет их, иначе берет файлы из signing/. Если задан только один из двух, сборка падает.
